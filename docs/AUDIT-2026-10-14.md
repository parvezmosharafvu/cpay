# Security and operations audit, 2026-10-14

Scope: the whole repository at `main` 729a4ea (database migrations and RLS,
Edge Functions, static site, CI), plus read-only checks of production
(`riumaeihemgznvgattoc`) through the Supabase API. Nothing in production was
written. Each finding gives its evidence and where it was fixed, or the exact
owner action when it cannot be fixed from the repository.

## Fixed in this branch (`claude/ops-hardening`)

| # | Severity | Finding | Fix |
|---|---|---|---|
| A1 | Medium | The 24-hour wait on a newly saved USDT address was enforced only by the payment service (instant path). `system_queue_withdrawal()` (auto-withdraw after a settlement) and `admin_request_withdrawal_for()` picked the saved address without checking `usable_after`, so an address saved minutes ago (for example after an account takeover) could be queued at once. Reproduced on a disposable database. | `20261014050000_withdraw_cooldown_all_paths.sql`: both use only an address past its wait; the admin path says why. Bodies are production's (md5 of `prosrc` matched production) with only those lines changed. Test: `ci/withdraw_cooldown_all_paths_test.sql`. Existing fixtures that saved an address and used it at once now age it first. |
| A2 | Medium | Admin two-step sign-in could be skipped in the browser: `login.html` asks for the code after the password has already stored an aal1 session, and no desk page checked the level, so a second tab or a reload opened the desk. (The server accepts aal1 only while `admin_mfa_required` is off; see the open row below.) | `loadProfile()` in `public/app.js` finishes the second step (or signs out) before any desk loads; fails closed on an error. Tests: `tests/frontend/second-step.test.mjs`. |
| A3 | Low-Medium | Rejecting or marking a withdrawal paid ran with the service role, so the audit trigger could not name the admin, and "Mark paid" (closing a payout without sending money) needed no recent sign-in. | `admin-actions` writes an `audit_log` row with the admin's id for both, and "Mark paid" uses the same step-up as a send; the admin pages retry after the password prompt. |
| A4 | Ops | Production health was red every 15 minutes since 14:01 UTC (Telegram alert each time): lease row 2608 was left open by a wallet isolate that died mid-lease. The wallet itself was fine (a new lease every minute). The check would stay red until the row aged out after a day. | The wallet Edge Function closes open lease rows right after taking the advisory lock (holding it proves their holders are gone). Test in `runtime_test.ts`. |
| A5 | Low | Cron secrets compared with `===` / `!==`. | `_shared/secret-compare.ts` (constant-time, unset never matches) in daily-report, ledger-backup, health and the wallet function's `cron/sync`. |
| A6 | Low | `user-withdraw` returned raw Postgres error text to the browser. | Generic message; detail goes to the function log. |
| A7 | Low | Password reset did not end other sessions. | `reset.html` signs out globally after the new password is saved. |
| A8 | Process | Nothing stopped a new migration numbered below one already on `main` (PR #98's `20261014010000` after production applied `…020000`/`…030000`). | CI step "New migrations sort after every migration on main". |
| A9 | Gate | The release gate only refuses Critical/High rows; admin MFA and the real-money pilot were Medium, so a release could pass with either open. | Both raised to High in `docs/RELEASE-BLOCKERS.md`, with three new owner rows. |

## Checked and fine (evidence)

- Production: all 55 `admin_*` SECURITY DEFINER functions check `is_admin()`
  (or the service role) first; every SECURITY DEFINER function in `public`
  pins `search_path`; RLS is on for every `public` table; emergency stops
  and `admin_mfa_required` are JSON booleans (all `false`); migrations end at
  `20261014030000`; six pg_cron jobs active, last runs succeeded.
- Settlement is idempotent (unique delivery id and invoice ref); withdrawals
  lock the profile row, reserve is idempotent on `quote_id`, a trigger keeps
  available ≥ 0.
- No XSS sink with unescaped data in `public/`; no open redirect; every CDN
  script has SRI; workflows have read-only permissions, pinned actions, no
  `pull_request_target`.
- The only key in the repository and its history is the public anon key.
